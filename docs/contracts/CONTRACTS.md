# PayrollPilot canonical contracts (v1.1, 2026-10-20 12:45 PM)

Change log: v1.1 blessed lane B fixture extensions: `TimeEntry.scheduled_job_id`, snapshot `policies` and `obligations`, `entity_refs.coverage`. `contract_version` stays "1".

**This file is the single source of truth for shared data shapes, event names, state machines, and API routes.** Every plan references it; none redefines it. Changes go through the lead (integrator) in a PR that bumps `contract_version` and lists affected tests. Private policy details (named allocations, real rates, phone numbers) never appear here; use fixture placeholders.

Implementation mirrors: `backend/payrollpilot/contracts.py` (pydantic v2, lead-owned, generated by hand from this file) and `web/src/contracts.ts` (lane D keeps in sync; `npm run check:contracts` compares JSON fixtures against both).

## 0. Conventions

| Topic | Rule |
|---|---|
| Money | Integer **cents** (`int`), field suffix `_cents`. Unknown = `null`, never `0`. Display via `formatMoney`. |
| Time worked | Integer **minutes** (`int`), suffix `_minutes`. `2h14` -> `134`. |
| Timestamps | ISO 8601 with offset, e.g. `2026-10-05T14:03:00-04:00`. Business dates `YYYY-MM-DD` in `business_tz` (`America/New_York` proposed, unconfirmed). |
| IDs | Strings. Prefix by kind: `cyc_`, `wkr_`, `job_`, `te_` (time entry), `rcpt_`, `cost_`, `exc_`, `msg_`, `res_` (resolution), `appr_`, `corr_` (correction), `ci_` (compensation item), `wb_`, `evt_`, `mem_`. Source IDs kept verbatim in `source_ref`. |
| Source refs | `{"system": "jobber"|"gusto"|"quickbooks"|"owner_export"|"fixture", "record_id": str, "url": str|null, "captured_at": ts, "snapshot_id": str}` |
| Versions | `contract_version: "1"`; `policy_version` string on cycle; approvals bind to `target_version` (a content hash of the thing approved). |
| Labels | Every record that could be mistaken for real carries `provenance: "real"|"cached"|"synthetic"|"seeded_issue"|"test_reply"`. UI must render it. |
| Null vs zero | Missing money/time is `null`. Readiness code treats `null` as a blocker, never as zero. |
| Append-only | Corrections, approvals, messages, events are never updated in place; new rows reference prior ids. |

Source writes and payroll submission have no executor in this pilot (`NotImplementedError("gated: P1")`).

```jsonc
 "scope": "2 of 2 quoters; job_01 only", "blockers": [{"code": "policy_missing:overhead", "label": "Overhead allocation method unresolved (O05)", "exception_id": null}],
 "unknown_amount": false, "calculation_version": "calc_v1", "last_computed_at": "..."}
// Stage summary line rule: list each item separately; never roll up to "complete".
```

Calculation functions (lane B, pure, `core/payrollpilot_core/`):
- `normalize_duration(text) -> minutes` (`"2h14"`->134; `"2.25h"`->135; invalid -> error)
- `weekly_minutes(entries, workweeks) -> {workweek_start: {worker_id: minutes}}`
- `gross_wages(minutes, rate_cents_per_hour) -> cents` (Decimal; round half-even at the end only)
- `quote_pool(eligible_profit_cents, quoters: list, prior_paid: dict) -> {pool_cents, shares: {worker_id: cents}, blockers: []}`; raises `PolicyMissing` when profit is null, quoters > 2, or profit <= 0.
- `cycle_profit_bridge(components) -> {"lines": [...], "result_cents": int|null, "blockers": []}` each component once, null if any required component null.
- `labor_revenue_ratios(base_wages_cents, total_labor_cents, eligible_revenue_cents) -> {"base_ratio": float|null, "total_ratio": float|null, "not_meaningful": bool}`
- `readiness_for(item, exceptions, policies) -> Readiness`
- `run_audit(cycle_snapshot) -> list[Exception]` (deterministic rules, no LLM)

## 4. Events (append-only `events` table; also the Agent Activity feed and Band post source)

`event = {"id": "evt_...", "at": ts, "cycle_id", "actor": "audit"|"resolution"|"payroll"|"owner"|"system"|"bridge", "type": <below>, "summary": str, "refs": {...}, "usage": {"model": str, "input_tokens": int, "output_tokens": int, "cost_usd": float}|null, "duration_ms": int|null}`

Types: `cycle.created`, `snapshot.captured`, `audit.completed`, `exception.detected`, `exception.state_changed`, `handoff.requested` (audit -> resolution), `handoff.accepted`, `message.drafted`, `approval.granted`, `approval.invalidated`, `message.sent`, `message.delivery_status`, `message.received`, `reply.parsed`, `clarification.needed`, `resolution.recorded`, `memory.written`, `memory.recalled`, `memory.applied` (recall changed next action), `correction.proposed`, `correction.applied`, `recalc.completed`, `readiness.changed`, `workbook.generated`, `workbook.verified`, `blocked.unauthorized_instruction` (T17), `budget.exhausted`, `run.stopped`.

## 5. HTTP API (backend, FastAPI, `http://127.0.0.1:8000`, JSON; all routes under `/api`)

| Method | Path | Body / returns | Owner |
|---|---|---|---|
| GET | `/api/health` | `{ok, contract_version, integrations: {photon, band, cognee, browser_use}: "tested"|"unverified"|"blocked"}` | A |
| POST | `/api/cycles/load` | `{source: "fixture"|"private_snapshot", name}` -> `PayrollCycle` | A |
| GET | `/api/cycles/{id}` | `PayrollCycle` with `stage1`, `stage2`, `coverage` | A |
| POST | `/api/cycles/{id}/audit` | runs `run_audit`, stores exceptions, emits events -> `{exceptions: [Exception]}` | A (calls B) |
| GET | `/api/cycles/{id}/exceptions?stage=&category=&state=` | `[Exception]` | A |
| GET | `/api/exceptions/{id}` | `Exception` + `messages` + `resolution` + `correction` | A |
| POST | `/api/exceptions/{id}/handoff` | audit -> resolution (Band post when enabled) -> `{event}` | C |
| POST | `/api/messages/draft` | `{exception_ids}` -> `MessageBatch` (draft; text from Resolution agent, validated) | C |
| POST | `/api/approvals` | `{kind, target_id, target_version, scope_text}` -> `Approval` | A |
| POST | `/api/messages/{batch_id}/send` | requires active approval; calls bridge -> `MessageBatch` (sent) | C |
| POST | `/api/inbound` | bridge -> backend; header `X-PP-Bridge-Token`; body `InboundMessage` (dedupe on `provider_message_id`) -> `{parsed: ParsedReply, exception_updates}` | C |
| POST | `/api/exceptions/{id}/clarify` | bounded follow-up draft within same recipient/scope -> `MessageBatch` draft | C |
| POST | `/api/corrections` | `{resolution_id, kind, after}` -> `LocalCorrection` (proposed, with impact) | B/A |
| POST | `/api/corrections/{id}/apply` | requires approval -> applies, reruns audit + readiness -> `{correction, readiness_changes}` | A (calls B) |
| GET | `/api/cycles/{id}/readiness` | `{stage1: Readiness, items: [CompensationItem]}` | B via A |
| GET | `/api/cycles/{id}/packet` | internal review packet JSON (period, identities, earnings, calc version, evidence, readiness, workbook ref) | B |
| POST | `/api/cycles/{id}/workbook` | generates xlsx -> `WorkbookArtifact {id, path(private), draft_version, sheets, verified_totals, original_updated: false, note}` | B |
| GET | `/api/events?cycle_id=&since=` | `[Event]` | A |
| POST | `/api/memory/recall-check` | `{query, scope}` -> `{hits: [...], applied: bool, next_action_before, next_action_after}` (T15 proof) | C |
| POST | `/api/run/stop` | cancels new actions; pending approvals stay pending | A |

Bridge (Bun, `http://127.0.0.1:3001`): `POST /send {batch_id, recipient, text, text_hash}` header `X-PP-Bridge-Token` -> `{provider_message_id, status}`; bridge re-checks `recipient == PP_TEST_RECIPIENT` and refuses otherwise. Inbound: bridge forwards every provider message to backend `/api/inbound`.
